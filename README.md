# SciAnim Studio

SciAnim Studio is a local-first system for producing reproducible, personally styled scientific animations with Manim. A scientist describes an animation in ordinary language or YAML; the system enforces a versioned stylesheet and typed scientific constraints; a storyboard composed of registered components is rendered into named checkpoint stills, each with a layout report; and final videos are produced from isolated, pinned family environments.

The repository started as a documentation-first handoff and is being implemented incrementally. Check `docs/IMPLEMENTATION_PLAN.md` for what exists and what does not; do not assume a feature works because it is specified.

## Key architectural choices

- Natural-language prompting is the comfortable interface; **versioned YAML** is the persistent authoritative specification.
- `animation.yaml` captures intent, typed equations and hard constraints; `storyboard.yaml` captures scenes with narration, registered component objects, explicit data bindings and named checkpoints.
- A **component registry** is the contract shared by the validator, the code generator and the renderer. Storyboards made of registered kinds render without hand-written code; `kind: custom` is the explicit escape hatch.
- Styles are semantic, inherited and versioned; the renderer receives a resolved token document with provenance and hash.
- **Checkpoints are named markers reached by the real animation flow**, captured in Manim's fast-forward mode, with a layout report (normalized bounding boxes per object) that drives machine-checkable visual QA and object-anchored feedback.
- Each storyboard scene is one Manim section, which gives per-scene videos and scene-level incremental rendering.
- Equations default to Typst, which installs from PyPI into the family lockfile; LaTeX is a per-family opt-in.
- Three distributions: `scianim-core` (contracts), `scianim` (control plane) and `scianim-bridge` (render side). The control plane never imports Manim; families depend only on the bridge.
- Family environments are pinned with `uv.lock` and declare their system requirements; `.venv` directories are never committed or shared.
- Shareable bundles contain manifests, sources (when permitted), specs, code and lockfiles rather than machine-specific environments.

## Developer setup and reproduction

Requirements: Python 3.12+, [`uv`](https://docs.astral.sh/uv/), and for rendering the Cairo and Pango
development headers (`libcairo2-dev libpango1.0-dev` on Debian or Ubuntu; Homebrew `cairo pango` on macOS) plus the
DejaVu Sans font or any font named in the style's fallbacks. No LaTeX and no system ffmpeg are needed: equations
go through Typst and video through PyAV, both pinned inside the family lockfile.

```bash
uv sync --group dev                                   # control plane (never installs Manim)
uv run scianim doctor                                 # prerequisites
uv run scianim workspace init workspace --with-example           # workspace/ with styles, the example family and its projects
P=workspace/families/computational_neuroscience/divisive_normalization
uv run scianim family env sync workspace/families/computational_neuroscience   # Manim + bridge, isolated (minutes once)
uv run scianim doctor --project $P
uv run scianim validate $P && uv run scianim style resolve $P
uv run scianim codegen $P                              # scene module from the storyboard
uv run scianim snapshot $P --all                       # four named checkpoints + manifest.json + review sheet
uv run scianim revision create $P -m "first cut"       # revisions/rev_0001, write-once
uv run scianim snapshot $P --revision rev_0001         # renders/rev_0001/<job>/
uv run scianim workspace list workspace                # families, groups, projects, duplicate ids
uv run scianim clean $P                                # media cache and superseded working renders
uv run scianim feedback add $P --snapshot equation_complete --object normalization_equation --text "..."
uv run scianim compare $P rev_0001 working             # pixel and layout differences, diff PNGs
uv run scianim serve --workspace workspace             # review UI and API on http://127.0.0.1:8765/
uv run pytest tests/unit -q                            # contracts, cascade, checks, isolation, workspaces, revisions
uv run pytest tests/integration -q -m integration      # real renders in a temporary workspace; skipped without uv
uv run --project workspace/families/computational_neuroscience pytest packages/scianim_bridge/tests -q
```

Outputs land in `<project>/renders/<revision>/<job>/`: one PNG per checkpoint, `manifest.json` with layout reports
and input hashes, and `review_sheet.html`. Worker logs are under `.scianim/jobs/<job>/`. `examples/` is read-only;
the workspace holds everything that changes.

## What exists today

Milestones 0 to 2 of the implementation plan are implemented and tested on the example: typed contracts and
JSON Schemas, file and project validation, versioned styles with a cascade that records provenance, workspaces
with families, groups and projects, `uv` family environments, the component registry with six kinds,
deterministic code generation, in-flow checkpoints with layout reports, content-addressed caching, write-once
revisions, shared assets, and a static review sheet. Milestone 3 adds the local review server (`scianim serve`):
a FastAPI API over the same files, a rebuildable SQLite index, typed feedback records in `feedback/*.yaml` with
object resolution from the layout report, render comparison, non-blocking render jobs with logs and cancel, and a
React front end built into the package (source in `ui/`). Not yet built: video rendering and sections, source
ingestion, agent operations, bundles. See `docs/IMPLEMENTATION_PLAN.md` for the checklist.

## Example status

The YAML and CSV files in `examples/` are **illustrative fixtures**. The dataset is synthetic. The personal stylesheet is provisional: it demonstrates token structure, not a finalized design language. References to papers or figures must be added from actual user-provided assets.
